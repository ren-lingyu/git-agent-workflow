#+title: v0.2.0 Release Notes

* Overview
This release adds local repository lifecycle management and repository-wide
inspection to the v0.1.0 runtime, retaining registration-based branch identity.

* Changed
** Protection and committed-state validation
- Extend protection from registered source branches to the complete
  =refs/gaw/*= namespace. The hook resolves symbolic-ref updates, preserves
  ordinary HEAD switches that do not move a protected branch, and rejects
  invalid registration queries rather than treating them as safe.
- =init= and =deploy= install or validate the canonical repository-local
  configured hook, including its enabled setting. Divergent configuration is a
  conflict. Controlled operations disable only the GAW-owned named hook.
- Share complete committed-state validation across check, deployment,
  initialization and status. A config marker alone does not prove validity.

** Build and implementation layout
- Move the Common Lisp system under =lisp/=, with its version in
  =lisp/VERSION=. Organize packages into pure core, Git-orchestrating runtime
  and public API layers; centralize protected mutations and worktree inventory.
- Replace the external =cl-nix-forge= build dependency with a repository-local
  ASDF/Nix library driving program and test operations.

* Fixed
- Avoid triggering GAW's own protection hook during worktree deployment and
  compensation cleanup.

* Added
** Initialization and deployment
#+begin_src text
  git gaw init --branch <name> [--worktree-path <path>]
  git gaw deploy [--branch <name>] [--worktree-path <path>]
#+end_src

- =init= checks for existing or ambiguous GAW history, metadata, hook and
  worktree conflicts, then creates an independent root with =(:workspace ())=.
  It installs the branch, registration and selector in one expected-state ref
  transaction before using normal deployment. A failed ref transaction may
  leave unreachable objects, but not a partially created ref graph.
- =deploy= selects an existing valid local branch. Without =--branch= it uses a
  valid selector or discovers local candidates; multiple candidates require
  explicit selection. It does not fetch or create a missing source branch.
- Deployment creates or validates local metadata, optionally materializes a
  linked worktree, checks an attached worktree and configures protection.
  Repeating deployment against the same valid state is safe.

** Registered branch lifecycle
- =git gaw branch -m <new-name>= renames the selected registered branch through
  native Git, then coordinates registration and selector metadata.
- =git gaw branch -d <name>= retains native safe-delete checks and removes the
  associated registration and selected-branch metadata after success.
- Preflight validation, expected-state updates, final checks and best-effort
  compensation address operations that cannot share one Git transaction.
  Partial failures are reported explicitly.

** Repository-wide status
- =git gaw status= inventories branches, registrations, selector, hook and
  worktree attachments from normal, nested, linked or bare repositories.
- Inspection supports files and reftable ref backends through Git interfaces.
  Enumeration is supplemented with exact probes derived from known branches and
  selector state.
- Default status exits zero when it produces a report, even when findings are
  unhealthy. Read the report; this is not a readiness-success signal.
- =status --diagnose= additionally runs Git connectivity diagnostics and
  combines their result with the GAW report's health criteria. It forwards Git
  output unchanged and may expose unrelated repository problems.

* Compatibility and migration
Portable state remains the ordinary branch, history, config and workspace.
Deployment metadata is local and rebuildable:

#+begin_src text
  refs/gaw/heads/<name> -> refs/heads/<name>
  refs/gaw/HEAD         -> refs/gaw/heads/<name>
#+end_src

Existing v0.1.0 history and the daily commands remain usable. Use the lifecycle
commands for setup instead of manually constructing new metadata. The selector
does not replace the current worktree HEAD as the authority for =commit=. Git
2.54 or newer remains required; packaged support remains x86_64-linux.

* Limitations
- No automatic fetching, remote enforcement, system-wide deployment or
  arbitrary corruption repair is introduced.
- A broken ref hidden by Git enumeration and not derivable from known selector
  or branch names can escape the default status inventory.
- Status is repository-wide inspection; =check= remains worktree readiness
  inspection. Neither command repairs metadata.
