#+title: v0.4.0 Release Notes

* Overview
This release adds a bundled persistent-memory skill and declarative ASDF/Nix
skill installation. Runtime source and command behavior remain unchanged from
v0.3.0.

* Changed
- Use =git-agent-workflow= as the Nix package name while keeping =git-gaw= as
  the executable.
- Separate project construction, generic scripts and skill installation in the
  ASDF/Nix helpers, and refresh the flake inputs used by the build.
- Expand README guidance for persistent memory, evidence horizons, project
  provenance, host authorization and skill packaging.

* Added
** Persistent-memory workflow
- Bundle the =git-agent-workflow= skill for recovering current goals,
  decisions, questions, provenance and next actions from the declared workspace
  before expanding into history.
- Maintain current memory as substantive work evolves, rather than waiting for
  handoff. Create checkpoints selectively when states have independent recovery
  value; session boundaries and project commits do not require matching nodes.
- Use check, edit, explicit staging, GAW commit and show inside a validated
  worktree. Lifecycle changes and ordinary project-history mutation remain
  separate authorized work.

** Historical reconstruction and provenance
- Reconstruct distinct recoverable states as separate first-parent checkpoints
  when their content and order are supported. Each snapshot must explain the
  whole durable state; do not replay messages or minor edits.
- Survey the user's full evidence horizon, including work predating existing
  memory. Account for substantive intervals before declaring coverage complete.
- Seek evidence for material gaps; if unrecoverable, report them and retain
  only supported evolution without inventing chronology.
- Attach project parents only for exact snapshots identified by existing work
  evidence. Current HEAD, timestamps and nearby commits do not establish older
  provenance. Missing provenance does not prevent a memory checkpoint; later
  validation grounds only the newly validated state.

** Declarative skill installation
- Install only static files explicitly declared in the ASDF =share/skills=
  component subtree. Each declared skill must contain =SKILL.md=.
- Enable installation by default in =mkProject=, with =installAgentSkills= set
  to =false= as an opt-out. A system with no skill subtree remains valid and
  installs none.
- Add fixtures checking declared files, exclusion of undeclared material,
  disabled installation and projects without a skill subtree.

* Compatibility and migration
Existing v0.3.0 histories and deployments remain valid. No runtime protocol or
CLI migration is required. Make the bundled skill available to the agent to
adopt the new workflow; installing an executable does not by itself establish
that a host has activated it. The command remains:

#+begin_src text
  git-gaw
#+end_src

* Limitations
Skill instructions guide agent behavior within host authorization; they do not
add runtime enforcement or authorize ordinary project mutations.
