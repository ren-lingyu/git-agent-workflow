#+title: v0.6.0 Release Notes

This release introduces versioned workspace configuration, strengthens checkpoint validation and forward compatibility, and expands the bundled agent skill into a more complete workflow for persistent memory, archival evidence, and project-specific skills.

* Changed
** Stronger protection for future configuration versions
- Added a structural version recognizer that runs before the full configuration parser.
- Recognized unsupported numeric versions and unrecognized leading version tokens without requiring the current parser to understand the remaining configuration syntax.
- Classified unknown versions as indeterminate, preserving conservative branch protection even when the =.gaw/config= marker remains unchanged.
- Preserved existing parsing behavior for v0/v1 configurations without a leading version declaration.
- Expanded regression coverage for unknown syntax, malformed configurations, branch protection, and recovery behavior.

Future configuration versions should place =:version= first. This forward-protection mechanism is available starting with v0.6.0; older executables cannot be expected to recognize future syntax.

** Expanded bundled agent workflow
Reorganized the bundled =git-agent-workflow= skill with dedicated guidance for:

- *Memory:* Maintaining recoverable working state, recording motivations and related issues, and distinguishing implementation, verification, and external tracking status.
- *Archive:* Preserving selected historical evidence through independent snapshots, using =MANIFEST.md= and =files/=, with explicit provenance, byte-level verification, and immutable checkpointed snapshots.
- *Project skills:* Creating, maintaining, and adapting project-specific skills, including transferring useful improvements between project and general workflows.

The skill also clarifies project-parent associations, discourages persistent semantic dependencies on GAW checkpoint OIDs, and distinguishes historical evidence from authoritative current instructions.

These are agent workflow conventions, not new CLI protocol requirements.

** Breaking compatibility change
*=git gaw commit= now rejects checkpoints that mix changes inside and outside =.gaw/=.*

A checkpoint may modify GAW protocol files or workspace files, but not both in the same commit.

This applies to additions, deletions, content modifications, mode changes, and cross-boundary moves. Validation compares the candidate tree against its first-parent tree and rejects mixed changes with =MIXED-PROTOCOL-CHANGES= before creating a commit object or updating a ref.

*Migration:* Separate protocol changes and workspace changes into distinct GAW checkpoints. Existing history is not retroactively rejected, and unchanged-tree project associations retain their previous behavior.

** Packaging and Testing
- Extended protocol and CLI regression tests for configuration versions, workspace roles, commit boundaries, and protection hooks.
- Added real Git integration tests covering future-version protection and marker-preserving recovery.
- Improved Cabal source-distribution and Nix build checks to verify bundled skill references and embedded help resources.
- Continued to support the existing Git-native workflow without introducing external archive tools or additional configuration commands.

* Added
** Versioned workspace configuration
- Introduced configuration v1 with optional role-based workspace groups, such as =:memory=, =:archive=, and =:skills=.
- Supported custom role names, repeated role groups, and mixing grouped and direct workspace declarations.
- Preserved the original configuration format as implicit v0, without requiring historical checkpoints to be migrated.
- Updated =git gaw init= to generate =(:version 1 :workspace ())= by default.
- Added non-blocking diagnostics for unknown v1 top-level fields, reported by =git gaw check= and =git gaw status=.
- Added =git gaw help config= as a dedicated reference for configuration syntax, workspace validation, and compatibility.

Role metadata does not change workspace path coverage or Git validation semantics.

* Compatibility
- Existing implicit and explicit v0 configurations remain supported.
- Historical checkpoints retain their original configuration semantics; no history rewrite or migration is required.
- Older GAW executables are not guaranteed to understand v1 or future configuration versions.
- Git 2.54 or newer remains required for configured reference-transaction hook support.
- The Haskell implementation is tested on x86_64-linux; other declared platforms remain unverified.
