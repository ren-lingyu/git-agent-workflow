#+title: v0.6.0 Release Notes

* Overview
This release adds versioned workspace configuration and role metadata,
strengthens checkpoint boundaries and forward protection, and expands the
bundled memory, archive and project-skill workflows.

* Changed
** Breaking: separate protocol and workspace changes
=git gaw commit= rejects candidates changing paths both inside and outside
=.gaw/=, with =MIXED-PROTOCOL-CHANGES=. The comparison is against the
first-parent tree and includes additions, deletions, content, modes and
cross-boundary moves. Rejection happens before commit-object creation or ref
update.

Stage and checkpoint protocol and workspace changes separately, keeping every
intermediate candidate valid. =git gaw check= does not replace this transition
check. Existing history, root initialization and unchanged-tree project
associations are not retroactively rejected.

** Initialization and bundled workflows
- New =init= roots contain =(:version 1 :workspace ())= without predefined
  directories. Declarations do not themselves create files or directories.
- Route memory, archive and project-skill procedures to dedicated references.
  Record objectives, motivations, related work, implementation status and
  verification separately, maintaining current knowledge promptly.
- Preserve selected original evidence as independent immutable snapshots with
  =MANIFEST.md= and =files/=, scoped provenance, byte verification and explicit
  sanitization limits. Historical material is evidence, not active instruction.
- Guide reusable skill creation and workflow transplantation, keeping temporary
  project progress in memory. Avoid durable semantic dependencies on checkpoint
  OIDs and keep project-parent choices tied to exact supported snapshots.

* Added
** Versioned configuration and workspace roles
- Read implicit and explicit v0 plus v1. V1 permits direct declarations,
  repeated role groups and custom role names; nested role groups and duplicate
  paths are rejected. Reserved entry names remain =file= and =directory=.
- Preserve role/group metadata while flattening the same effective workspace
  for validation. Roles add no inheritance, precedence or Git protection, and
  directory names do not invent roles for v0 or ungrouped declarations.
- Report unknown v1 top-level field names as non-blocking warnings in check and
  status. Values still satisfy restricted syntax and resource limits; v0
  continues to reject unknown fields. Check distinguishes HEAD/index warnings.
- Add =git gaw help config= for syntax, path coverage, limits and
  compatibility.

** Forward protection and regression coverage
- Recognize unknown leading version values before the full v0/v1 parser. An
  unsupported numeric or unrecognized version token makes branch state
  indeterminate and preserves protection even with an unchanged marker.
- Enforce shared structural limits without interpreting future-version bodies.
  Missing/malformed leading values and malformed structure remain invalid.
- Add configuration, CLI and real-Git cases for roles, unknown versions,
  marker-preserving recovery and mixed checkpoint boundaries.
- Extend source-distribution and installed-resource checks for the skill
  references and embedded help.

* Compatibility and migration
No rewrite is required for implicit or explicit v0 histories. Supported older
configs retain their own checkpoint semantics; old executables need not read
v1. When introducing a future config version, place =:version= first after the
opening parenthesis, apart from whitespace/comments. Accepted nonleading v0/v1
configs remain readable through the compatibility path, but that path cannot
protect unknown future syntax. Use a compatible executable for unsupported
versions; v0.5.0 cannot retroactively gain v0.6.0's forward protection.

Split future protocol/workspace edits as described above. Git 2.54 or newer
remains required. Refresh the bundled skill to adopt its expanded workflows.

* Limitations
The CLI treats workspace prose as opaque. Roles and skill conventions do not
add natural-language enforcement. The recorded tested platform is x86_64-linux;
other declared platforms remain unverified.
