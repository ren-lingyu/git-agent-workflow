#+title: v0.7.0 Release Notes

* Overview
This release adds independent Auxiliary source histories while formal GAW
remains the authority for project-current memory. Source trees are not merged
into formal memory by creating parent associations.

* Changed
** Breaking: reserve Auxiliary names
Reserve the entire =_gaw_aux_= branch-name range, including malformed names.
Existing branches in that range receive name-based protection even when config
is missing or damaged, and formal initialization/rename cannot enter it. Review
existing branches using this prefix when upgrading.

** Inventory and diagnostics
- Separate formal, Auxiliary and ordinary branches in status; inspect reserved
  Auxiliary branches using their UUID-relative committed layout.
- Report the pre-cleanup branch/worktree inventory during undeploy, mark
  unavailable inventory explicitly, and warn when the shared protection hook
  was actually removed. Histories and worktrees remain intact.
- Update hook rejection wording and human-readable output. Consumers matching
  diagnostic text should be reviewed.

* Added
** Independent source histories
#+begin_src text
  git gaw aux init [--worktree-path <path>]
  git gaw aux deploy --branch <name> [--worktree-path <path>]
  git gaw aux check [--branch <name>]
#+end_src

- Create a secure canonical lowercase UUIDv4 branch =_gaw_aux_<uuid>= whose
  tree is confined to the matching =<uuid>/= subtree. The root contains only
  =<uuid>/.gaw/config= copied byte-for-byte from the selected formal commit. It
  copies no uncommitted config, workspace content or formal-history parents.
- Interpret declarations relative to the UUID subtree. Run ordinary =commit=
  and =check= at the Git worktree root, not within the UUID directory. Apply
  the existing protocol/workspace transition boundary to logical UUID-relative
  paths.
- Require a valid formal selector and the existing canonical shared hook for
  Auxiliary init/deploy. These commands do not change the selector, install or
  repair hooks, fetch, or create registries. Deployment uses an existing source
  branch and may remain repository-only without a worktree path.

** Inspection and deletion
- =git gaw check --branch <name>= checks formal or Auxiliary committed state
  without a target worktree or the caller's index/operation readiness. It is
  not a worktree-readiness report.
- =aux check= reports structural validity separately from safe-deletion
  readiness. Valid unintegrated history still succeeds. Without a current
  Auxiliary worktree, specify =--branch=.
- Extend =branch -d/-D= to valid Auxiliary histories with no associated
  worktree. Safe deletion requires the source tip to be retained in the formal
  history selected by =refs/gaw/HEAD=; it verifies selector, formal tip and
  source tip in one ref transaction.
- Forced deletion explicitly permits abandonment without formal retention, but
  keeps validity, worktree and conditional source-tip checks. Continued object
  reachability is not guaranteed. Neither mode removes worktrees or other refs.
- Worktree registrations are checked separately before and after deletion, with
  race detection and conditional compensation. Serialize worktree lifecycle
  activity with branch deletion; this is not full transactional isolation.

** Source reconstruction and integration guidance
- Bundle guidance for evidence-backed source reconstruction, uncertainty,
  reconciliation of decisions, formal knowledge integration and archive reuse.
- Associate exact relevant Auxiliary checkpoints through normal additional
  parents when justified, preserving ancestry without merging trees or adopting
  every source claim. Preserve substantive context in formal memory.
- Recover retained source files through the associated committed history after
  branch deletion. Retaining an intermediate checkpoint does not retain a later
  source tip or make it safe to delete.
- Extend embedded help and skill resource checks, plus protocol/application
  coverage for lifecycle, layout, ref/worktree races and compensation.

* Compatibility and migration
Existing formal history, v0/v1 configuration and formal branch deletion
semantics require no migration or rewrite. Upgrade both the interactive
executable and the executable used by the shared hook before creating/importing
Auxiliary histories, and keep the bundled skill compatible. Older executables
cannot validate or protect the new UUID layout.

Ordinary commit gains no new deployment prerequisite. Auxiliary init/deploy
have the explicit selector/hook requirements above; undeploy may remove the
shared protection used by both kinds of history.

* Limitations
There is no Auxiliary rename, retire, abort, discard or separate executable.
Knowledge integration remains an explicit agent/reviewer workflow. Git 2.54 or
newer remains required. The original release notes record x86_64-linux
verification and 13 help/5 skill resources; declared aarch64 platforms are not
evidence of completed platform testing or new validation during this backfill.
