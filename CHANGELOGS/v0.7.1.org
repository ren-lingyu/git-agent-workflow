#+title: v0.7.1 Release Notes

* Overview
This release extends the bundled skill with knowledge establishment and
cross-source consolidation. CLI commands, configuration and Git history
protocol remain unchanged.

* Changed
** Discovery lines and independent retention decisions
- Treat Auxiliary histories as independently evolving discovery lines that may
  span sessions, agents or alternating work. Integrate intermediate stages into
  formal memory while sources continue developing, without a one-to-one mapping
  between agents, sources or checkpoints.
- Permit interleaved integration of several lines and several source parents in
  a formal stage. Select the exact inspected state, not an unexamined latest
  tip; later ancestry retention does not replace an earlier stage's
  association.
- Assess knowledge integration, raw-evidence archival and source Git-history
  retention separately. Reading or adopting a source does not mandate a parent.
  Associations need relevant exact-state evidence and an acceptable authorized
  ancestor-retention boundary; audit, explanation or recovery can supply value.

** Selection and sanitization
- Screen before writing memory, archives, skills, checkpoint messages or
  staging, including newly retained parent ancestry. A clean source tip does
  not prove the absence of sensitive content in its ancestors.
- Prefer the smallest sufficient evidence set. Do not retain whole
  conversations, routine logs, large test output or temporary directories by
  default.
- Reassess newly acquired material even from an existing path or source,
  complete justified memory/capture actions promptly within authorization, and
  avoid duplicate snapshots merely because material was obtained again.
- Distinguish authorized original bytes from sanitized derivatives and record
  evidence limits. History deletion or GC is not routine sanitization.
- Prefer English for newly authored GAW content while preserving necessary
  original wording and explicit user/project language requirements.

* Added
** Establishment
- Provide a dedicated workflow for an absent or materially insufficient
  baseline in formal GAW or Auxiliary. Bound knowledge and evidence, identify
  gaps and build a resumable understanding with motivations, decisions and next
  actions.
- Reuse existing reconstruction/provenance rules; establishing current
  knowledge cannot prove older observations. A sufficient baseline returns to
  normal maintenance rather than requiring establishment for every acquisition.

** Consolidation
- Compare overlapping, conflicting, obsolete and incomplete knowledge scopes
  against formal memory. Preserve unresolved material disagreements rather than
  manufacturing consensus or treating recency as proof.
- Support central, authorized distributed or hybrid investigation, coordinating
  formal writes and reconciling intervening work before checkpoints.
- Use project documents, conversations, existing histories or Auxiliary sources
  directly; converting every source into an Auxiliary or archive is optional.
- Bundle Establishment and Consolidation references in Cabal data and update
  workflow routing, README and upgrade guidance.

* Compatibility and migration
Existing histories and archive snapshots need no rewrite or migration. Refresh
the installed bundled skill when upgrading from v0.7.0; updating the executable
alone does not establish host adoption. Formal memory remains authoritative for
the project, while Auxiliary uses the same evidence standard within its scope.

* Limitations
The new procedures are skill guidance, not new CLI enforcement, permission to
delegate, or permission to retain unsafe history. Completed consolidation does
not imply every historical assertion was rerun or any source must be deleted.
