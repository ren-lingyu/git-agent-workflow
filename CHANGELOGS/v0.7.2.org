#+title: v0.7.2 Release Notes

This release improves the bundled GAW agent-memory skill, clarifying the interpretation of Git history, refining project memory navigation, and making archival assessment conditional rather than routine.

*No CLI commands, configuration formats, or Git protocol semantics have changed.*

* Changed
** Historical Dependency Semantics
- Clarify that GAW commit parents represent historical dependencies needed to interpret durable knowledge states.
- Distinguish first-parent knowledge inheritance from additional historical context supplied by exact project or Auxiliary commits.
- Clarify that parent edges are not citations, knowledge-adoption records, approval markers, or validation results.
- Preserve existing parent-selection criteria without introducing additional necessity tests or mandatory per-parent explanations.

** Conditional Archival Assessment
- Separate routine source inspection and memory maintenance from archival assessment.
- Trigger archival evaluation only for explicit preservation requests or concrete independent evidence needs.
- Allow a completed evaluation to result in no capture, without requiring per-acquisition archival records.
- Prevent references between source materials from automatically expanding archival scope.
- Preserve existing archive snapshot, manifest, verification, and authorization requirements.

** Source History Recovery
- Recover checkpoint ancestry, external-parent relationships, and retained-history reachability directly from Git rather than maintaining parallel static indexes in memory.
- Clarify that Auxiliary UUIDs provide structural separation, not stable knowledge-source identity.
- Improve guidance for recovering relevant source history from retained Git objects and committed trees.

* Added
** Project Memory Entry-Point Skills
- Recommend a minimal project-level memory entry-point skill when formal GAW explicitly declares a =:skills= workspace role.
- Prefer adapting an existing suitable skill over creating a duplicate.
- Keep entry-point skills focused on memory navigation and interpretation rather than duplicating memory content or Git-derived relationships.
- Avoid imposing the same entry-point requirement on Auxiliary histories merely because they inherit the configuration.

* Upgrading
Upgrading from v0.7.0 or v0.7.1 requires *no workspace migration or Git history rewriting*.

Refresh the installed bundled skill to adopt the updated guidance. Updating the executable alone does not guarantee that an agent environment is using the new skill.

Existing checkpoints and archive snapshots retain their original conventions.
