#+title: v0.7.2 Release Notes

* Overview
This release clarifies historical dependencies, memory entry points and
conditional archival assessment in the bundled skill. It does not change CLI
commands, configuration formats or Git protocol mechanics.

* Changed
** Historical dependencies and source recovery
- Describe first parents as inherited knowledge history and additional parents
  as relevant external historical context through exact commits. Associated
  trees are not merged. Edges are not citations, knowledge-adoption records,
  approval markers or validation results.
- Preserve the established exact-state parent-selection criteria without adding
  a new necessity test, mandatory per-parent explanations or fixed business
  roles for additional-parent positions.
- Recover ancestry, source relationships and retained-history reachability from
  Git and committed trees, using memory for substantive explanations and
  evidence limits instead of parallel static UUID/checkpoint indexes.
- Clarify that Auxiliary UUIDs provide structural separation and collision
  avoidance, not durable semantic source identity, provenance or chronology.
- Retain a relevant source state for justified historical context, not merely
  to keep objects reachable or make a branch deletable.

** Conditional archival assessment
- Routine source inspection, memory maintenance, establishment, consolidation
  and Auxiliary work no longer trigger archival assessment by default.
- Begin an assessment for an explicit preservation request or a concrete
  independent original-evidence need. Knowledge integration, capture and parent
  selection remain separate judgments, not a mandatory per-source checklist.
- Within an active assessment, reassess newly acquired candidates under the
  same selection threshold. An evaluation may result in no capture; ordinary
  work needs no per-acquisition archive decision record.
- References do not transfer archival value or recursively expand capture
  scope. Preserve the existing snapshot, manifest, byte-verification,
  sanitization and authorization requirements once capture is justified.

* Added
- Recommend a minimal project-level memory entry-point skill when formal GAW
  explicitly declares a =:skills= role. Prefer adapting an existing suitable
  skill; no fixed name, layout or extra specialized procedure is required.
- Use the entry point for memory navigation, reading order and interpretation
  conventions. Reference existing memory rather than duplicating facts or
  Git-derived relationships, and maintain it when organization or
  interpretation changes rather than after every session.
- Do not infer the requirement from directory names or apply it independently
  to an Auxiliary merely because it inherits a =:skills= role.

* Compatibility and migration
Upgrading from v0.7.0 or v0.7.1 needs no workspace migration or history
rewrite. Refresh the installed bundled skill to adopt this guidance; updating
the executable alone does not prove adoption. Existing checkpoints and archives
retain their original conventions.

* Limitations
Skill guidance does not add runtime validation of natural language or authorize
new lifecycle, archival or project-history mutations.
