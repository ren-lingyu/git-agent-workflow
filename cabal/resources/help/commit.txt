usage: git gaw commit [--allow-empty] [--allow-empty-message]
                      (-m <message> | -F <file>)...
                      [--] [project-commit...]

Create a commit on a valid GAW branch from the complete current index.
Unstaged and untracked files are not included.  The command must run at the
GAW worktree root.

Nonempty messages require a printable ASCII title: type(scope): subject
Type and scope are nonempty tokens without spaces, parentheses or colons;
custom values and scopes such as skills/example are allowed. Use exactly one
space after the colon and a nonempty subject without leading or trailing spaces.
The title ends at EOF, LF or CRLF. The body is not format-checked or rewritten.
Review "Checkpoint messages" in the git-agent-workflow skill for semantics.
--allow-empty-message permits only a zero-byte message to skip this check.
Existing history is not revalidated against these title rules.

Options:
   -m, --message <message>    append a UTF-8 commit message fragment
   -F, --file <file>          append exact message bytes; '-' reads stdin
       --allow-empty          allow an unchanged tree without project parents
       --allow-empty-message  allow an empty commit message

Additional external commits (project snapshots or Auxiliary checkpoints) become parents after the previous GAW commit.
Their trees are checked for conflicts but are not merged into the GAW tree.

HEAD and staged configs are decoded independently. A valid v0 checkpoint may
be followed by a v1 checkpoint without changing the old config. Unsupported
versions fail explicitly; role groups use the same workspace and project
parent validation as direct declarations. Config warnings are not printed.

A new checkpoint may change paths inside .gaw/ or outside it, but cannot
change both in the same commit. This includes additions, deletions, content,
mode changes and cross-boundary moves, compared with the first-parent tree.
Mixed changes fail with :MIXED-PROTOCOL-CHANGES before a commit object or ref
update is created. Unchanged-tree commits retain the existing rules above.
Existing history and root initialization are not checked retroactively.

A canonical Auxiliary branch uses <uuid>/.gaw/config and UUID-relative workspace
paths, but invocation stays at the Git worktree root. Protocol-change isolation
is relative to that UUID root. Parent conflicts use actual Git tree paths.
The selector and hook remain optional for commit, including after undeploy.
